# SwiftLeaf PDF: independent comparison rereview

Review date: 2026-10-25. Source baseline: `ae97db1d56c67a2294ebb82606f85144fbbf91c0` (main). Review branch: `t3/rereview`. Only this report changed. No source fixes.

**Verdict:** the October 23 comparison substantially understates today's source capabilities. Searchable OCR, Unicode replacement, interactive merge, Office exports, advanced form data exchange, compare, batch actions, sanitation, page production, comments interchange and unified undo now have implementations. This is no longer merely a reader with a few overlays. **Acrobat Pro parity remains unproven and materially incomplete.** Scanner acquisition is a blank-page implementation; TSA retrieval discards its result; accessibility tagging does not connect tags to content; PDF/A conversion can manufacture a false conformance label. These matter more than adding another tool row.

## Method, comparators, confidence

- Read `docs/comparison-pdfcraft.md`, CHANGELOG, the top-level `docs/*.md` feature/development material, `src/ToolsPanel.cpp`, and corresponding command dispatch, engine and worker implementations. Followed important paths below the UI; command registration alone never counts as completion.
- Local worktree HEAD equals the requested repository's local main. No fetch/rebase or source edits. Evidence locations refer to that baseline, not future main. `path:line` cites the beginning of relevant code; surrounding statements establish qualifications.
- **I = implemented:** useful end-to-end source path exists for the stated scope. **P = partial:** useful subset or correctness/workflow gaps. **M = missing:** no working exposed path for that scope found. I does not mean runtime-tested, production-safe or equal output fidelity.
- PDFCraft means the **same pinned native source** used by the old comparison: `c9ac28a04843141f2261ade4b9a19d51aed6f182`. Browser PDFCraft remains separate, pinned at `53e469252b616aa0ac654efa267d2e92ac821866`. Both local comparison clones still match these hashes. This is not a claim about their latest October 25 releases. Native/browser capability baselines otherwise retain the original report's qualifications.
- Acrobat means Acrobat Pro desktop workflows, supplemented by official Adobe documentation linked below; no Acrobat executable, output corpus or subscription service was exercised. No assumption that Acrobat handles every PDF perfectly. Cloud signing and cross-device services are separately identified.
- **Static review only.** No build, GUI, scanner, Office automation, OCR recognition, certificate/TSA or saved-file forensic tests ran. Existing tests inspected are evidence of intended coverage, not fresh passing results. Release size, memory, startup and Authenticode were not remeasured. Old 0.4.1 measurements cannot describe this enlarged HEAD binary.
- Missing-feature findings are bounded by inspected UI/dispatch/backend paths and repository searches; library support or an experimental `src/ng` implementation is not a released Win32 workflow.
